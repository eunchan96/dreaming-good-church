# 공지·일정 관리

- 관리자: `/admin/community` (주보 관리자와 같은 편집자 계정)
- 공개 공지: `/notices`, 공개 일정: `/events`
- 조회 API: `GET /api/community?kind=notice|event`, 선택적으로 `&id=UUID`

## 주보 중심 공지

저장된 주보에서 일반 글 항목을 선택하고 ‘별도 공지로 가져오기’를 누른다.
제목·본문·웹 공개 여부를 복사한 **초안**이 생성된다. 관리자 화면에서 검토 후 ‘게시 설정 저장’을 눌러야 공개된다.
같은 주보 항목을 다시 가져오면 기존 공지를 재사용하며 중복 생성하거나 기존 공지를 덮어쓰지 않는다.
비공개 주보 항목은 비공개 설정을 유지한다. 설교·헌금 등 구조화 블록을 공지로 잘못 가져오지 않도록 일반 글만 지원한다.

공지 문구를 바꿔도 기존 주보는 바뀌지 않는다. 반복 공지는 ‘새 공지 초안으로 복사’로 재사용한다.
복사 시 게시 기간은 초기화하며 내용·공개 설정·민감정보 표시는 유지한다.

## 일정과 주보 포함

시작/종료는 한국 시간(Asia/Seoul)으로 입력하며 DB는 timestamptz로 저장한다. 종료는 시작보다 빠를 수 없다.
‘다음 주 일정으로 복사’는 시작/종료를 7일 뒤로 옮긴 초안을 만들고 게시 기간을 초기화한다.
일정이나 공지를 선택해 주보에 복사하면 그 시점의 내용을 일반 글 블록으로 저장한다.
일정 블록에는 한국 시간·장소·설명이 포함되며, 공개 설정과 다음 주 재확인 표시도 유지한다.
이후 원본 수정·보관·비공개 변경은 주보 복사본에 전파하지 않는다. 주보의 공개 설정은 별도로 검토해야 한다.

## 공개와 보관

새 항목의 공개 기본값은 true이나 상태는 draft다. 공개 조건은 모두 충족해야 한다:

1. status=published
2. is_public=true, sensitive=false
3. 게시 시작이 비어 있거나 현재 시각 이전
4. 게시 종료가 비어 있거나 현재 시각 이후 (종료 시각부터 제외)

민감정보 표시를 켜면 공개 체크를 해제하고 공개 전환을 막는다. DB에서도 두 값의 모순을 거절한다.
‘초안 저장’은 게시를 취소하며, ‘보관’은 목록에 기록을 남기면서 공개 메뉴에서 내리는 되돌릴 수 있는 삭제다.
보관된 항목은 다시 초안으로 저장해 복원할 수 있다. 공개 기간 변경은 해당 메뉴에만 적용된다.
관리 화면은 수동 저장이며, 입력 오류·충돌 시 입력을 유지한다. 다른 화면과의 충돌은 revision으로 거절한다.
세션 종료 시 숨긴 입력은 같은 계정으로 재로그인하면 현재 탭에서 복구한다. 다른 계정 로그인 시 이전 입력은 제거한다.

## 권한·API

`community_entries`에 RLS를 적용했다. 등록 편집자만 전체 조회·삽입·수정 가능하다.
익명 사용자는 공개 기간 내의 공개 항목과 허용된 내용 열만 조회한다. 원본 ID·민감정보 표시·내부 상태는 공개하지 않는다.
API는 편집자 세션이나 서비스 키를 사용하지 않으며 no-store로 최대 100개를 반환한다.
공개 화면은 15초 주기 및 탭 복귀 시 갱신한다. 종료·비공개·보관된 항목의 ID 조회는 404다.

RPC:
- `save_community_entry(p_id,p_revision,p_entry)`: 검증·충돌 확인 후 저장.
- `create_notice_from_bulletin(p_bulletin,p_item,p_revision)`: 동일 시점의 원본에서 공지 초안 생성/기존 연결 반환.
- `copy_community_to_bulletin(p_entry,p_bulletin,p_revision)`: 초안에 내용 복사 및 revision 증가.

기존 `copy_bulletin_draft`는 게시된 원본도 복사하도록 보완했다. 원본 주보와 블록을 한 조회 스냅샷으로 읽은 뒤 새 초안과 블록을 생성한다. 게시 중 수정 제한은 유지한다.

## 후속

자동 반복 일정 생성·반복 예외, 공지와 주보의 자동 동기화, 페이지네이션, 최종 디자인은 지원하지 않는다.
첫째·셋째 주 오후예배 등 월별 자동 규칙은 별도 WBS 작업에서 다룬다.
