# 홈 문구·사진 관리

## 2026-11-14 관리자 화면 간소화

기능 연결에 이어 홈 관리의 세부 UI를 정돈했다. 전체 너비 제목 아래에 빠른 목차를 배치하고 ‘이 페이지’는 제거했다. 미리보기→반영 버튼→첫 화면 문구→사진 순서다. 미리보기 제목 오른쪽에는 PC/모바일 두 버튼만 표시하며, 실제 콘텐츠 높이를 iframe에서 전달해 하단의 빈 여백을 없앤다. 메시지는 같은 origin과 해당 iframe에서 보낸100~5000px의 유한한 높이만 받는다. 다른 window의 위조 메시지는 무시한다.

‘이렇게 반영하기’와 ‘이전 설정 불러오기’를 미리보기 바로 아래에 배치했다. 후자는 현재 공개된 마지막 저장값을 불러오는 기존 기능이며 과거 버전 기록이 아니다. 미저장 폐기 확인과 버전 충돌 거절을 유지한다.

문구 제목 오른쪽에는 최신 버전/수정 중만 표시한다. 제목·설명은 각각 두 칸을 가까이 묶고 각 줄12자/48자 제한을 한 번만 표시한다. 버튼/환영 문구도 같은 행 정렬을 쓰며 모바일에서 라벨을 위로 옮긴다. 입력의 접근성 이름은 유지하고 placeholder로 대체하지 않는다.

이미지는 작은 썸네일과 ‘새 이미지 선택’을 기본으로 보여준다. 선택하면 기존 업로드/검증을 바로 실행하되 공개는 반영 버튼을 눌러야 한다. 새 파일 설명은 ‘교회 홈페이지 대표 이미지’로 시작하며 ‘이미지 세부 설정’에서 실제 내용을 적을 수 있다. 기존 사진의 설명을 새 사진에 그대로 붙이지 않는다. 설명은 스크린리더용이고 본문 캡션이 아니다. 잘라 채우기/전체 보이기·틀 비율·사진 초점과 보관함 재사용은 접힌 세부 설정으로 옮겼다. 보관함은 기존 업로드 재사용 목록이며 카테고리 기능은 없다. 파일 업로드 실패 시 기존 선택을 유지하고 재시도/취소한다.

검증: 홈CMS 브라우저 시나리오와 공통 관리자/목차/교회설정/재로그인 포함7건 통과, 초기 미리보기 높이/최소 너비/닫힌 옵션/스크린샷·최대 문구/사진 교체/저장 회귀1건 재검증. 타입·lint·격리 production build 통과. 로컬 합성 사진/임시 계정은 테스트에서 정리했다. DB/API/권한/운영 콘텐츠 변경은 없다. 최신 검수 주소와 CI 결과는 Notion의 같은 홈 관리 가이드에 기록한다. 아래 초기 기록의 버튼명과 미리보기3종 설명은 이번 변경 전 UI다.

## 편집과 반영

관리자 상단의 홈페이지 관리에서 첫 화면 제목2줄, 설명2줄, 교회 소개 버튼과 하단 환영 문구를 편집한다. 기존 값이 없으면 현재 디자인의 기본 문구/일러스트를 편집란에 보여주며 방문만으로 DB에 쓰지 않는다. 인사말·교회 정보는 기존 교회 정보 관리로 연결한다.

제목은 줄마다 권장8자·최대12자, 설명48자, 버튼24자, 환영80자다. 줄바꿈 문자는 받지 않는다. 글자 수만으로 레이아웃을 보장하지 않고 실제 글꼴 로드/너비 변경 때 제목 크기를 맞춰 각 입력 줄을 유지한다. 공개 화면과 미리보기가 같은 HomeHero를 사용한다.

현재 입력은 공개 설정과 분리돼 있다. 저장하고 홈페이지에 반영을 누르고 공개 확인을 승인해야 현재 문구/사진을 한 번에 바꾼다. 다른 탭의 저장 이후 낡은 버전은 거절하고 입력을 보존한다. 다시 불러오기는 미저장 변경을 확인한 뒤 현재 공개 값을 읽는다. 세션 종료 시 폼/iframe을 숨기고 같은 계정 복구·다른 계정 입력 초기화, 메뉴 이동/로그아웃 이탈 확인을 제공한다.

## 사진·일러스트

기본 교회 일러스트, 사진(cover), 일러스트(contain)를 선택한다. 누끼만 허용하지 않으며 투명 PNG/WebP도 기존 정규화 과정에서 투명도를 보존한다. 세로4:5/정사각형1:1/가로4:3과 사진 초점0~100%를 조절한다. 사진은600×400px 이상, 일러스트는256×256px 이상이다. 이미지 설명은 필수/최대200자다.

기존 보관함을 재사용하거나 새 정지 JPEG/PNG/WebP를 올린다. 홈 편집기의 새 파일은4MB까지 받아 Vercel의4.5MB 요청 한도보다 작게 보낸다. 서버의 기존 정규화로 실제 형식을 검사하고 긴 변2400px 이하 WebP로 변환하며 EXIF/위치정보를 제거한다. 참고: https://vercel.com/docs/functions/limitations#request-body-size .

업로드는 새 UUID 파일을 만들고 아직 공개하지 않는다. 반영 전에는 인증된 이미지 요청의 blob URL만 미리보기에 사용한다. 업로드 실패 시 기존 선택·공개 사진을 바꾸지 않는다. 현재 홈페이지에서 참조한 사진은 FK로 삭제를 막는다. 사진 교체/기본 일러스트 복귀 후에도 과거 주보에서 사용 중이면 계속 삭제할 수 없다.

## 실제 너비 미리보기

같은 origin의 /admin/home/preview iframe 안에서 실제 공개 Hero를 렌더링한다. PC1280·모바일390/320px로 바꾸고 편집 영역에 맞게 축소한다. iframe 자체 너비를 바꾸므로 실제 미디어쿼리/글꼴/줄바꿈을 확인할 수 있다. 미리보기 안의 링크는 이동하지 않는다.

부모→자식은 정확한 origin·window source를 검사하고 허용 구조/길이의 설정과 같은 origin blob URL만 받는다. 준비 완료 handshake와 onLoad로 초기 저장값도 동기화한다. URL/query/localStorage/API에 미저장 문구·토큰·blob을 저장하지 않는다. preview 단독 접근은 기본 문구만 표시하고 관리자/미리보기 경로 모두 noindex다. 로그아웃 시 iframe을 제거한다.
