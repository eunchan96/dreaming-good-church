# 공개 홈페이지와 반응형 탐색

Figma는 참고 자료로 유지하고 실제 구현 화면에서 검토한다는 사용자 결정에 따라 홈과 공통 탐색을 구현했다.

- `/`: PC 환영 영역, 주보 바로가기, 소개·공지·다가오는 일정. 실제 공개 API만 사용한다.
- 768px 이상: 상단 탐색과 2열 콘텐츠. 그 미만: 1열과 주보·공지·일정·교회 안내 하단 탭. 홈은 교회명 또는 홈 링크로 접근한다.
- 관리자 화면에는 공개 홈페이지 탐색을 적용하지 않는다.
- 공개된 교회 소개가 없으면 준비 안내를 표시한다. 대표 사진과 공식 비전 문구는 아직 입력하지 않았다.
- 각 홈 영역은 독립 조회하며 실패하면 이전 내용을 비우고 재시도 버튼을 표시한다. 15초 및 창 포커스 복귀 시 새로 조회한다.
- 본문 16px, 조작 영역 최소 44px, 키보드 포커스와 본문 바로가기, 현재 메뉴 표시, 모바일 안전 영역을 적용했다.
- 홈의 소식 링크는 해당 전체 목록으로 이동한다. 개별 공지 상세 주소는 후속 작업이다.

검증: 타입 검사, ESLint, 프로덕션 빌드, 320/390/768/1440px 탐색·가로 넘침과 조회 실패 복구 Playwright 검사. 공개 API/권한 규칙은 변경하지 않았다.

## 주보 읽기 화면

- PC: 본문 옆 고정 목차. 모바일: 가로로 넘기는 구역 바로가기.
- 목차는 공개 API가 반환한 항목만 사용한다. 이동한 본문 구역에 키보드 포커스가 놓인다.
- 지난 주보 목록은 기본 접힘이며 발행 월로 필터링한다. 현재 API의 최근 100개 범위만 검색하고 화면에도 이 제한을 표시한다.
- 같은 주보를 다시 선택하면 본문을 지우지 않는다. 다른 주보를 선택하면 이전 본문·목차를 지운 뒤 새 내용으로 교체한다.
- 조회 실패 시 본문·목차를 제거하고 재시도를 표시한다. 로딩/빈 목록에는 오류 재시도 버튼을 표시하지 않는다.
- 검증: 프로덕션 실행에서 320/390/768/1440px 넘침·목차 포커스·월 필터·선택 유지 검증 1건, 로컬 DB에서 게시/취소·비공개 보호 및 샘플 검증 2건 통과. PC/모바일 스크린샷 확인.

후속: 날짜별 주보 주소·링크 복사·공유 미리보기, 100개를 넘는 기록 조회, 다른 공개 페이지의 공통 스타일 통일, 실제 대표 사진·소개 반영. 인쇄 지면과 HWP 가져오기는 별도 WBS 범위다.
