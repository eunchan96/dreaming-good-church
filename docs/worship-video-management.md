# 예배 영상 관리

## 관리자 사용

상단의 예배 영상 관리에서 새 영상을 등록한다. 예배 종류(주일/오후/금요/새벽), 예배 날짜, YouTube 링크와 제목을 입력하고 실제 영상을 확인한다. 초안 저장은 비공개이며 공개 저장은 확인 대화상자 후 공개한다. 보관은 삭제 없이 공개 목록에서 제외한다. 보관/초안 영상을 다시 공개할 수도 있다.

YouTube watch·youtu.be·live·shorts·embed 링크 또는11자리 ID를 받는다. 허용한 YouTube 호스트에서 ID만 추출하며 임의 URL을 서버에서 요청하지 않는다. 채널에서 링크를 복사해 등록하므로 API 키가 필요 없다. 제목/설명/썸네일로 예배 종류를 자동 확정하지 않는다. 채널 후보 자동 수집은 보조 후속 기능이다.

예배별 대표는 하나다. 대표 미지정 시 최신 예배 날짜의 공개 영상부터 표시한다. 같은 종류의 동일 영상은 중복 저장할 수 없다. 수정 중 메뉴 이동·로그아웃은 확인하고, 실패 시 입력을 보존한다. 다른 계정으로 재인증하면 이전 계정 입력을 버리며 같은 계정은 현재 탭에서 이어간다.

## 공개 목록

큰 직접 YouTube iframe과 날짜·제목, 아래 가로 썸네일 목록을 제공한다. 터치/좌우 이동 버튼/Tab·Enter로 선택하며 영상 선택으로 자동 재생하지 않는다. 홈은 대표만 표시한다. 이전 영상 더 보기로20개씩 이어 읽는다. 별도 대표는 처음에 포함하며 뒤 페이지와 중복하지 않는다.

등록 없는 주일은 기존 최신 영상 연결을 유지한다. 오후·금요·새벽은 준비 중 및 채널 링크를 표시하며 정리되지 않은 과거 재생목록을 임의로 대표로 쓰지 않는다. API 장애는 빈 목록과 구분해 오류·재시도를 제공한다. 이번 목록은 관리자가 등록한 전체 영상이며 유튜브의 모든 과거 영상을 자동 가져온다는 의미가 아니다.

## 스키마와 권한

`20261113093440_worship_video_library.sql`은 새 worship_videos 테이블·인덱스·RLS와 security invoker 저장 함수를 추가한다. 기존 자료를 복사/게시/수정하지 않는다. 일반 인증 사용자에게는 교회 편집자 멤버십이 있어야 읽기/쓰기가 가능하다. 익명은 published행의 공개 열만 SELECT하며 DELETE/함수 실행은 불가하다.

저장 함수는 ID+revision으로 덮어쓰기를 방지한다. 대표 변경은 transaction advisory lock 아래 기존 대표 해제와 대상 저장을 한 트랜잭션으로 처리한다. 대상이 충돌/중복이면 기존 대표 해제도 롤백된다. 예배별 대표 부분 unique인덱스와 예배종류·날짜/ID 공개목록 인덱스를 둔다.

`/api/worship/videos`는 서버 공개 키·익명 RLS로만 조회하며 인증 헤더/서버 키를 쓰지 않는다. 허용 예배 종류·날짜/UUID 커서만 받고, 날짜 내림차순+ID 내림차순으로21개 조회 후20개+다음 커서를 반환한다. 별도 대표 조회는 첫 페이지에서만 수행한다. 응답은no-store이며 초안·보관·revision을 반환하지 않는다.

## 목차 이동

관리자 모든 화면에 적용한다. 클릭 시 대상 포커스를 preventScroll로 옮긴 후 scrollIntoView smooth로 이동하고 URL hash를 replace한다. 동작 줄이기 선호에서는 instant를 사용한다. 고정 상단/모바일 목차에 가려지지 않게 scroll-margin을 둔다.

## 백업 호환

영상 테이블이 있는 DB는 해당 행을 백업 inventory와 복구 후 값/행 수 비교에 포함한다. 도입 전6테이블 백업도 지원한다. 마이그레이션 파일은 실제 DB 이력에 있는 것만 포함하므로 배포 전 미적용 파일이 복구 이력 비교를 깨뜨리지 않는다. 알 수 없는 테이블 inventory나 적용된 파일 누락은 거절한다.

## 검증과 적용 순서

- 로컬 CLI v3 대상이127.0.0.1:54322임을 확인했다. 첫 query 명령은 자동 검토가 모호한 대상을 이유로 거절했고, 도움말/로컬 URL 확인 후 허용됐다. CLI의 여러 SQL문 prepared statement제약 때문에 명시적 로컬 컨테이너 psql로 실행했다.
- 로컬 보안/성능 advisors경고 없음. migration repair로 검증 적용 이력을 정리하고 db pull의 shadow 재생 및 차이 없음,7개 파일/이력 일치 확인.
- 관리자·공개 흐름 신규2건 및 기존 공통 UI/홈5건 통과: 초안/보관 비노출, 멤버십 회수/비편집자 거절, 대표 변경과 충돌 롤백,24개 동일/다른 날짜 페이지, 키보드 선택, 네트워크 실패 입력 유지, smooth 실제 호출/스크롤,1440/768/390/320px·자체 접근성. 외부 YouTube 플레이어 내부는 검사 범위에서 제외했다.
- 단위 테스트·타입/lint·격리 출력 빌드 통과. 새 테이블 포함 SQL 백업의 격리 컨테이너 복구·값/행수·RLS 검증과 성공/실패 후 컨테이너 제거 통과.

원격 연결은 최신 사용자 암호화 백업 생성 → Drive사본 검증 → 추가 마이그레이션 적용/익명 권한 검증 → Preview 연결 검증 순서다. 이 기록 시점에는 백업 답변 대기이며 운영 연결 DB 미적용이다. Production/main 병합·실제 영상 게시는 포함하지 않는다.
